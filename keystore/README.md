# 签名文件

`debug.keystore` 是**调试用**签名，口令是 Android 调试签名的通用口令（storePassword 与
keyPassword 均为 `android`，别名为 `androiddebugkey`）。

## 为什么放进版本库

安卓要求：覆盖安装时新包的签名必须与已装的一致，否则只能卸载重装，而卸载会清掉
手机上的全部记录。安卓默认的调试签名保存在用户目录下，会随构建环境变化而重新生成，
已经出现过一次"签名漂移导致更新装不上"的情况，所以这里固定一份并纳入版本库。

## 注意事项

- 这份签名**只能用于开发**。正式发布必须另建发布签名，且发布签名与其口令**绝不能提交**。
- 换成发布签名时，因为签名不同，仍然需要卸载重装，务必先用应用内的「导出备份」留底。

## 正式签名（发布用）

发布包用 `release.jks`，口令与别名写在 `release.properties` 里，这两个文件都在 `.gitignore` 中，
**不会进版本库**。构建时 `app/build.gradle.kts` 会自动读取；文件不存在时只会打出未签名的 release 包，
不影响别人克隆下来编译和跑测试。

```
keystore/
├── debug.keystore       # 调试签名，入库
├── release.jks          # 正式签名，不入库
└── release.properties   # 正式签名的口令，不入库
```

两条务必记住：

1. **把 `release.jks` 和 `release.properties` 备份到别处**（比如私有的密码管理器）。
   丢了就再也无法给已发布的 App 发更新，只能让用户卸载重装。
2. 因为签名不同，调试包和正式包**不能互相覆盖安装**，切换时现有记录会被系统清掉，
   切换前先在应用里导出一次备份。
