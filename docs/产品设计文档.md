# 工作快速记录 — 产品设计文档

版本 v0.1 ｜ 2026-09-16 ｜ 状态：MVP 方向已确认

## 1. 背景与问题

目标用户是中小学里负责维护电子教学设备的老师，日常接触的多媒体教室、班班通、投影、电子白板、功放、教学电脑等设备，出故障、换耗材、做巡检都需要留痕。

他们的记录过程在三个环节上都不顺：

- **采集慢**：现场手里拿着工具，很难停下来打字。
- **整理累**：月底或期末要交台账，零散记录得重新抄一遍。
- **没动力**：不记也不影响当下干活，但考核、工作量证明的时候又需要。

现有的替代方案（微信收藏、手机备忘录、纸质本子）能记下来，却交付不了——这些记录最后要变成一份能给领导看的材料。

## 2. 产品定位

一句话：让设备维护老师在手机上十秒记一条，月底一键导出成能直接交上去的工作台账。

核心判断是，这个产品的差异化不在"能记录"，而在"能交付"。会打字、能录音的工具到处都是，缺的是从零散记录到正式台账这一段。所以第一版的重心是导出的形态，而不是功能的多少。

## 3. 核心使用场景

**场景 A｜现场即记**：修完投影，掏手机，从快捷入口直达新建，地点一点即填，语音说一段，顺手拍两张照，保存。目标十秒内完成。

**场景 B｜事后补录**：当天忙忘了，晚上翻着相册补记，时间需要能手动改。

**场景 C｜月度交付**：月末收到提醒，选本月范围，导出图文报告，打印或发微信给领导。

**场景 D｜回查历史**：搜索或翻列表，确认"这间教室上次修的是什么问题"。

## 4. MVP 功能范围

### 4.1 一条记录包含什么

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 时间 | 是 | 年月日时分。新建时自动填当前时间，可手动修改以支持补录 |
| 地点 | 是 | 文本输入，自动补全历史地点，常用地点置顶 |
| 问题与解决方法 | 是 | 一段自由文本，支持语音输入 |
| 照片 | 否 | 1–9 张，优先调用 App 内相机直接拍摄 |

设计原则：必填项越少越好。地点是唯一需要高频重复输入的字段，必须做到一点就选，否则"十秒记一条"不成立。"问题与解决方法"保持一段自由文本，不做拆分，因为第一版不做分类统计，拆开只会增加输入负担。

### 4.2 功能清单

**记录**

- 新建记录，桌面快捷入口可直达
- 语音输入转文字，复用系统或第三方输入法的语音能力
- 拍摄或选择照片，支持多张
- 编辑、删除记录
- 记录列表按时间倒序，带照片缩略图
- 搜索地点与内容关键词

**导出**

- 选择时间范围，导出图文报告
- 报告中的照片嵌入文件本体，不引用原图路径，避免用户清理相册后报告出现空白
- 报告内容为：标题、时间范围，以及逐条记录（时间、地点、问题与解决方法、照片）
- 不含抬头与签名
- 照片统一压缩后写入报告，控制文件体积，保证能通过微信发送
- 全部数据导出，作为备份，包含原始照片

**提醒**

| 层级 | 形式 | 触发方式 |
| --- | --- | --- |
| 第一层 | 打开 App 时的顶部提示条，可就地导出 | 距上次导出超过阈值 |
| 第二层 | 桌面小组件，显示上次导出时间，超期变色或加提示文字 | 持续显示 |
| 第三层 | 通知 | 每月 1 号提醒一次，用户可关闭 |

第三层选择按日历触发而非按累计天数触发，是因为老师交台账本来就是按月交的，按月份提醒更贴合真实节奏，也更容易被接受。

### 4.3 明确不做

- 账号、登录、云同步、多人协作
- 工单派发、审批流
- 统计图表、故障分类、绩效指标
- 设备资产档案、耗材库存管理
- 桌面图标按时间变色（评估结论：国产手机桌面对动态图标支持不稳定，容易导致图标丢失；颜色本身缺少语义；红绿渐变对色盲用户不成立）
- iOS 版本

## 5. 关键约束

- **纯本地**：不需要账号，不需要服务端，完全离线可用。这既是优势也是约束。
- **数据只存在设备上**：因此"导出全部数据"是必要的备份手段，不是附加功能。
- **数据丢失不可恢复**：卸载 App、换手机、手机丢失都会导致记录消失，需要让用户知情，并在长期未导出时给出提醒。
- **语音能力外置**：依赖系统或第三方输入法，App 内不从零实现语音识别。

## 6. 后续迭代方向

- 导出为可编辑表格，便于学校二次汇总
- 故障类型标签与按标签筛选
- 自动定时导出与备份
- 云端同步、多人共享台账
- 设备二维码，扫码直接调出该设备的历史记录

## 7. 待确认事项

- 提示条触发的"长期未导出"阈值，建议 30 天
- 报告文件格式，PDF 优先，是否同时提供便于微信发送的图片版
- 常用地点是否需要按楼栋分组
