# 工作快录 — 技术方案文档

版本 v0.1 ｜ 2026-09-16 ｜ 状态：技术选型已确定，待进入环境搭建

本文档说明如何实现《产品设计文档》中定义的 MVP，只覆盖第一版需要的技术决策、关键流程与风险，不做逐模块的详细设计。

## 1. 技术选型

### 1.1 结论

采用**原生 Android**：Kotlin + Jetpack Compose。

### 1.2 选型理由

这个应用约九成的工作量在调用系统能力——桌面小组件、相机、通知、后台定时、文件分享、私有存储、图像与文档渲染，真正"画界面"的部分占比很小。跨平台框架的价值主要在界面层，而本项目明确不做 iOS，这份价值拿不到，成本却要全额支付。

另外两点是硬约束：

- **桌面小组件**在 Flutter 和 React Native 中都无法直接实现，最终仍要写原生代码，最难的部分省不掉。
- **语音输入**依赖系统输入法。原生文本框直接走系统输入法协议，兼容性最稳；跨平台框架自行实现输入法协议，在国产输入法上存在兼容风险，而语音是本产品的核心输入方式。

补充考虑：APK 体积与启动速度。目标用户机型较杂，原生应用体积明显更小。

### 1.3 备选方案对比

| 方案 | 小组件 | 语音输入 | 体积 | 结论 |
| --- | --- | --- | --- | --- |
| Kotlin + Compose | 原生支持 | 最稳 | 小 | **采用** |
| React Native | 需第三方库或原生 | 依赖插件 | 中 | 备选：仅当维护者更看重能自行读懂代码 |
| Flutter | 需原生配合 | 有兼容风险 | 较大 | 不采用：要学新语言，小组件照样写原生，又没有 iOS 收益 |
| 网页 / PWA | 无法实现 | — | 极小 | 不成立：桌面小组件与定时通知做不到 |

| 项 | 取值 |

## 2. 技术栈清单

| 用途 | 选型 |
| --- | --- |
| 语言与界面 | Kotlin + Jetpack Compose |
| 数据存储 | Room（记录、照片索引），DataStore（上次导出时间、提醒开关） |
| 相机 | 系统相机，通过 `ACTION_IMAGE_CAPTURE` + `FileProvider` 调用 |
| 相册选择 | AndroidX 照片选择器（`PickVisualMedia`），不需要读取相册权限 |
| 图片加载 | Coil（列表与详情页缩略图） |
| 图片压缩 | 系统 `BitmapFactory` 采样 + `ExifInterface` 校正方向 |
| PDF 导出 | 系统自带 `PdfDocument` 与 `Canvas`，配合 `StaticLayout` 处理中文换行 |
| 桌面小组件 | Jetpack Glance |
| 定时提醒 | WorkManager（一次性任务，执行后重排下一次） |
| 分享 | `FileProvider` + `ACTION_SEND` |
| 备份包 | `kotlinx.serialization` 生成 JSON，`java.util.zip` 打包原图 |
| 依赖注入 | 不引入框架，使用手写的应用级容器 |
| 测试 | JUnit + Robolectric（电脑上跑），少量 Compose UI 测试 |
| 构建 | Gradle Kotlin DSL，JDK 17 |

关于依赖注入：第一版只有个位数模块，引入 Hilt 会增加构建复杂度与编译时间，收益有限。等模块数量明显增长后再考虑替换。

## 3. 架构分层

保持三层，不做过早抽象：

- **界面层**：Compose 页面与组件，只负责展示与收集输入。
- **领域层**：用例（新建记录、导出报告、生成备份、计算是否需要提醒），承载全部业务规则，也承载单元测试。
- **数据层**：Room 数据库、文件存储、系统能力封装（相机、通知、小组件、分享）。

目录按功能分包，而不是按类型分包，便于后续增删功能。

## 4. 数据模型

### 4.1 记录

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| occurredAt | 记录时间（年月日时分），可手动修改 |
| place | 地点文本 |
| description | 问题与解决方法的自由文本 |
| createdAt / updatedAt | 用于排序与排查问题 |

### 4.2 照片

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| recordId | 所属记录 |
| relativePath | 相对 App 私有目录的路径，不存绝对路径 |
| width / height | 用于 PDF 排版时预留比例 |
| orderIndex | 在一组照片中的顺序 |

### 4.3 存储策略

- 照片保存在 App 私有目录，不写入系统相册。
- 保存时统一压缩：长边不超过 1600 像素，JPEG 质量 85，单张约 200–400KB。
- 数据库只存相对路径。换设备、迁移目录时不受影响。
- PDF 中嵌入的照片再做一次更小的压缩（长边 1280、质量 80），控制报告体积。

## 5. 关键流程

### 5.1 新建记录

1. 桌面快捷方式或列表页悬浮按钮进入新建页。
2. 时间自动填当前时间。地点输入时按历史地点做前缀匹配，常用地点置顶。
3. 描述框由系统输入法负责语音转文字，App 不做任何处理。
4. 拍照调用系统相机，通过 `FileProvider` 给出一个 App 私有目录中的目标地址，相机应用把原图直接写入该位置；相册选择走系统照片选择器。
5. 保存时压缩照片并入库，返回列表页并提示成功。

关于相机权限：如果应用清单里声明了 `CAMERA` 权限，那么调用 `ACTION_IMAGE_CAPTURE` 反而需要先申请该权限。本方案不声明该权限，由系统相机自行处理，应用侧无需授权弹窗。

### 5.2 PDF 导出

1. 按选定时间范围查询记录，按时间正序排列。
2. 用 `PdfDocument` 输出 A4 尺寸页面，正文用 `StaticLayout` 绘制以正确处理中文换行。
3. 每条记录先测量高度：地点与时间一行，正文若干行，照片按比例缩放后排布。剩余空间不足时另起一页，记录不跨页截断。
4. 输出到应用缓存目录，通过 `FileProvider` 分享；同时提供"保存到文件"写入用户选定位置。

### 5.3 提醒

- **提示条**：每次打开列表页时比对 DataStore 中的上次导出时间，超过阈值则显示。
- **通知**：用 WorkManager 排一个"下个月 1 号 09:00"的一次性任务，任务执行时发出通知并立即重排下一次。
- **小组件**：Glance 实现，显示上次导出日期与超期天数，由 WorkManager 每天刷新一次，应用启动与导出完成后也主动刷新。

国产系统可能延迟或抑制后台任务，因此提示条是提醒机制中唯一不依赖后台调度的一层，必须实现。

### 5.4 备份导出

导出一个压缩包，内含 `records.json` 与全部原始照片。导入时校验版本号后写回数据库与文件目录。这是纯本地方案下唯一的数据保险，属于必需功能。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 部分国产系统的相机应用忽略目标地址参数 | 拍照后拿不到照片 | 调用返回后校验目标文件是否生成，失败时提示并引导改用相册选择 |
| 照片方向标记未处理 | PDF 中照片躺倒 | 读取时解析方向标记并旋转，作为图片管线的固定步骤 |
| 中文在 PDF 中换行异常 | 报告排版错乱 | 统一用 `StaticLayout` 绘制文本，不使用 `Canvas.drawText` 直接排版 |
| 报告体积过大 | 微信发送受限 | 嵌入前二次压缩，并在导出页提示预计体积 |
| 后台任务被系统限制 | 每月提醒不触发 | 三层提醒机制，提示条不依赖后台调度 |
| 数据只存本机 | 换机或丢失即不可恢复 | 备份导出与长期未导出提醒 |
| 目标机型系统版本差异 | 功能可用性不一致 | 最低支持 Android 8.0，真机覆盖测试 |

## 7. 开发环境

### 7.1 已安装的工具链

开发机为 Windows（x64）。项目位于 `E:\project\worklog`，工具链放在项目下的 `toolchain` 目录中，随项目一起管理，不依赖系统盘，也不在系统目录留下残留。路径全部使用英文，避免构建工具在非 ASCII 路径上出问题。

| 组件 | 版本 | 位置 |
| --- | --- | --- |
| JDK | Temurin 17.0.20.1 | `toolchain\jdk17` |
| Gradle | 8.11.1 | `toolchain\gradle-8.11.1` |
| Gradle 缓存 | — | `toolchain\gradle-home` |
| Android 命令行工具 | 23.0 | `toolchain\AndroidSdk\cmdline-tools\latest` |
| Android 平台 | android-36 | `toolchain\AndroidSdk\platforms\android-36` |
| 构建工具 | 36.0.0 | `toolchain\AndroidSdk\build-tools\36.0.0` |
| 调试工具 | platform-tools 37.0.1 | `toolchain\AndroidSdk\platform-tools` |

用户级环境变量已配置 `JAVA_HOME`、`ANDROID_HOME`、`ANDROID_SDK_ROOT`、`GRADLE_USER_HOME`，并把 JDK、platform-tools 与 Gradle 加入 `PATH`。其中 `GRADLE_USER_HOME` 指向项目内的 `toolchain\gradle-home`，构建缓存因此也留在项目内。

`toolchain` 目录已写入 `.gitignore`，不会进入版本库。

### 7.2 三点注意

- `sdkmanager` 已被官方标记为弃用，推荐改用命令行工具中的 `android` 命令（`android sdk install`），并且 SDK 许可协议不再需要手动接受。现有用法仍可用，但后续新增 SDK 包时优先使用新命令。
- 因为工具链与构建缓存都在项目文件夹内，常规编译与测试不需要额外授权。只有 adb 例外：它会往用户目录写调试密钥，连接真机时仍需要一次授权。
- 项目目录曾从中文路径迁移到 `E:\project\worklog`。如果环境变量被重置或换机器，需要把 `JAVA_HOME`、`ANDROID_HOME`、`GRADLE_USER_HOME` 重新指向 `toolchain` 下的对应目录。

### 7.3 调试方式

使用真机而非模拟器：模拟器占用大、在低配机器上体验差，且本项目最需要验证的相机与语音输入，只有真机才能反映真实表现。真机通过 adb 连接，建议使用无线调试。

### 7.4 AGP 9 的三个坑

搭工程时实际踩到的问题，记下来避免重复排查。

- **不能再引用 `org.jetbrains.kotlin.android` 插件。** AGP 9 自带 Kotlin 支持并默认开启，再声明该插件会直接构建失败，提示插件已不再需要。Kotlin 版本由 AGP 决定，本项目为 2.2.10；Compose 编译器插件仍需保留，版本必须与之一致。
- **compileSdk 至少要 37。** 新版 AndroidX 库（core-ktx 1.19.0 等）要求调用方编译版本不低于 37，用 36 会直接报错。本机已装 android-37.0 与 android-37.2。
- **Gradle 包装器下载发行包可能卡住。** 实测 JVM 下载 `services.gradle.org` 会长时间无进展，而用系统自带下载工具则很快。遇到这种情况，把发行包直接放到 `toolchain\gradle-home\wrapper\dists\<哈希目录>\` 下即可，校验通过后包装器会自动解压。

## 8. 测试策略

配合项目根目录 `AGENTS.md` 的要求，每次改动都必须补测试并全部通过后再提交。

- **电脑上运行（JUnit + Robolectric）**：覆盖全部业务规则，包括 PDF 分页计算、地点补全与排序、日期范围计算、照片压缩尺寸换算、提醒阈值判断、备份包的生成与解析。
- **真机 / 模拟器运行**：只覆盖关键界面路径，例如新建记录后出现在列表中、导出按钮能产出文件。这类测试数量要少，避免拖慢每次提交。
- **纯文档改动**：没有可执行的测试，验证方式为结构检查（章节完整性、表格与列表格式）与内容回读确认，并在提交说明中写明本次改动不含代码。

为了让业务规则可测，PDF 分页、地点补全等逻辑必须写成不依赖 Android 框架的纯函数，由用例层调用。
